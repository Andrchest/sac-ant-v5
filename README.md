# SAC × Ant-v5

Алгоритм и весь эксперимент находятся в **`sac_ant_v5.ipynb`**. `train_sac.py` выполняет его code cells как обычный Python-процесс — без Jupyter и без второй копии алгоритма. `sac_monitor.py` отвечает только за наблюдение и визуализацию. Старые notebook outputs — результат первого smoke test; viewer показывает актуальный фоновый run.

## Фоновый запуск с красивой панелью

1. Запустите короткую проверку в отдельной tmux-сессии:

   ```bash
   cd /home/andreipc/Inno-RL
   tmux new-session -d -s ant-sac '.venv/bin/python -u train_sac.py'
   ```

   По умолчанию: **20 обучающих эпизодов**, не миллион шагов. Никакого notebook kernel не требуется. Новые зависимости мониторинга перечислены в `requirements-monitor.txt`; в текущем окружении они уже доступны.

2. Откройте живую панель:

   ```bash
   tmux attach -t ant-sac
   ```

   Панель показывает elapsed, приблизительную ETA обучения, шаги, эпизоды, steps/s, gradient updates, среднюю награду и мини-графики reward/evaluation/actor/critic loss. `Ctrl+B`, затем `D` отсоединяет терминал **без остановки обучения**. `Ctrl+C` в процессе обучения останавливает его; snapshots и уже сохранённые checkpoints остаются. Автоматического возобновления незавершённого эпизода нет.

3. Либо подключите независимый read-only viewer:

   ```bash
   .venv/bin/python watch_sac.py
   ```

   Viewer можно закрыть через `Ctrl+C` — обучение продолжится. `--once` печатает один snapshot. Для конкретного run: `.venv/bin/python watch_sac.py artifacts/ant_sac_smoke_...`.

ETA рассчитана **на текущий обучающий seed**, включает накладные расходы промежуточной оценки и графиков, но не включает baseline, финальную оценку, сохранение и видео. В smoke она рассчитывается по завершённым эпизодам, в full — по шагам. Длины эпизодов случайны, поэтому ETA может заметно колебаться. До первого завершённого эпизода показывается `estimating…`. Во время baseline/evaluation панель продолжает считать elapsed и показывает текущую фазу. Viewer предупреждает о snapshot старше 10 секунд: процесс мог завершиться аварийно.

## Подробные интерактивные графики

1. Запустите TensorBoard отдельным процессом:

   ```bash
   tmux new-session -d -s ant-tensorboard '.venv/bin/python -m tensorboard.main --logdir artifacts --host 127.0.0.1 --port 6006'
   ```

2. Откройте **http://127.0.0.1:6006** в браузере.

Сервер привязан только к localhost. Если обучение на другой машине, используйте SSH forwarding (`ssh -L 6006:127.0.0.1:6006 USER@HOST`), а не публикацию порта на всех интерфейсах. В TensorBoard доступны награда, длина эпизода, evaluation return, actor/critic loss, коэффициент энтропии и число gradient updates; новые данные сбрасываются примерно каждые 3 секунды.

## Графики в ноутбуке без запуска обучения

1. Откройте `sac_ant_v5.ipynb`.
2. В верхней ячейке **«Фоновое обучение и живые графики»** задайте `VIEW_BACKGROUND = True`.
3. Выполните **только эту ячейку**.

`RUN_TO_VIEW = None` выбирает последний фоновый run; можно указать точный путь. `AUTO_REFRESH = True` обновляет PNG и счётчики каждые 2 секунды. Остановка viewer-ячейки не влияет на внешний процесс. Не нажимайте «Run all», если требуется только просмотр: остальные ячейки запускают отдельное обучение.

## Что сохраняется во время работы

Каждый запуск получает отдельный каталог `artifacts/ant_sac_MODE_TIMESTAMP/`:

- `progress.json` — атомарный live snapshot, статус/фаза, elapsed/ETA/speed и последние точки кривых;
- `live_curves.png` — обновляемый график (примерно раз в 5 секунд и при evaluation);
- `seed_N/live_episodes.csv`, `live_metrics.csv`, `live_evaluations.csv` — метрики по мере поступления;
- `tensorboard/seed_N/events...` — интерактивные графики;
- `events.log` — события мониторинга;
- обычные артефакты эксперимента: config, best/final checkpoint, replay buffer, CSV, итоговый PNG, MP4, summary.

`artifacts/latest_run.json` указывает на последний **запущенный**, не обязательно успешно завершённый процесс. Для параллельных runs указывайте точный каталог viewer. Старые эксперименты не перезаписываются. PNG/JSON заменяются атомарно, чтобы viewer не читал половину файла. При отсутствии TTY используются обычные периодические строки вместо ANSI-анимации: можно запускать через `nohup` и читать лог; все PNG/CSV/TensorBoard продолжают обновляться.

## Другие бюджеты — только по явному запросу

```bash
# Всё ещё короткая проверка, но 40 эпизодов:
.venv/bin/python train_sac.py --episodes 40

# Полная конфигурация сетей, ограниченная 50 тысячами шагов:
.venv/bin/python train_sac.py --mode full --steps 50000

# План презентации: 1 млн шагов для каждого из трёх seed (долго):
.venv/bin/python train_sac.py --mode full --seeds 42 43 44
```

Full требует явного `--mode full`; его warmup равен 10k шагов, оценка — каждые 50k. Smoke и full используют разные размеры сетей и не являются одним продолжающимся экспериментом. Высокий return за стояние на месте не означает, что Ant научился идти вперёд: смотрите также x-progress и видео.

## Ночной запуск с дедлайном и продолжением

```bash
# Дата и timezone обязательны; пример ночи до 07:00 MSK:
.venv/bin/python -u overnight_sac.py --until 2026-10-22T07:00:00+03:00
```

Supervisor сначала запускает **1 млн шагов**. После сохранения модели, replay, таблиц и видео он проверяет 10 итоговых эпизодов. Рабочая эвристика достаточной походки: mean return ≥2500, mean x-progress ≥20 м, mean length ≥900, падения ≤20%. Это не статистическое доказательство и не сравнение алгоритмов. Если цель ещё не достигнута, продолжает **ту же модель, optimizer и replay** порциями до 250k шагов. Следующая порция уменьшается с учётом измеренной скорости и времени; общий предохранитель — 3 млн шагов за ночь.

Обучающие шаги прекращаются за 3 минуты до дедлайна, чтобы успеть выполнить финальную оценку, сохранение и видео. Если процесс зависнет, supervisor дополнительно отправит SIGINT за 90 секунд, SIGTERM за 30 секунд и SIGKILL в сам дедлайн. При частичном бюджете `summary.json` явно содержит `budget_completed=false` и `stop_reason=deadline`: это не выдаётся за завершённый миллион.

Каждые 100k шагов атомарно сохраняется полный комплект model+replay+metadata; остаются два последних таких комплекта. Финальные, best и предыдущие эксперименты не удаляются. `Ctrl+C` дополнительно пытается сохранить emergency-комплект. Полный replay занимает около **1.7 ГБ**, поэтому нужны свободные RAM и диск.

Решения и отчёт: `artifacts/night_TIMESTAMP/status.json`, `report.md`, `round_001.log` и далее. `artifacts/night_latest.json` содержит путь к ночной сессии. Эти файлы обновляются независимо от чата — вопросы и пробуждения агента не нужны. При ошибке supervisor сохраняет причину и останавливается, а не скрывает её бесконечными перезапусками.

Ручное продолжение полного checkpoint на дополнительные 250k шагов:

```bash
.venv/bin/python train_sac.py --mode full --steps 250000 --resume artifacts/ant_sac_full_TIMESTAMP/seed_42/sac_final.zip
```

Можно также передать `.../checkpoints/step_N/model.zip`, если рядом есть полный `replay_buffer.pkl`. Smoke-модель как full не принимается. Продолжение не сбрасывает глобальный счётчик шагов, а ETA и скорость учитывают только новую порцию.

## Кампания харденинга (мульти-сид, абляции, бейзлайны)

Отдельные скрипты для воспроизводимых экспериментов (окружение/награда/оценка —
идентичны ноутбуку, обучение идёт в отдельном процессе, параллельно):

- `run_experiment.py` — один эксперимент (SAC/PPO/TD3, свои гиперпараметры/шаги/сид).
- `campaign_experiments.py` — определения экспериментов (база + абляции + бейзлайны).
- `ablation_campaign.py` — оркестратор с приоритетами, N воркерами и дедлайном.
- `campaign_analysis.py` — сводка результатов кампании в markdown-таблицы.
- `campaign_plots.py` — графики (сиды, сходимость, абляции, бейзлайны).
- `best_config_campaign.sh` — запуск best config (3 сида параллельно).
- `best_config_plots.py` — графики сравнения best config и базы.
- `make_rollout.py` — запись rollout MP4 из checkpoint (только инференс).
- `best_vs_base_stats.py` — описательные средние по training seed; без некорректного pooled-эпизодного вывода.
- `stochastic_eval.py` — стохастическая (temperature) оценка robustness модели.
- `make_slide.py` — готовый слайд результатов (16:9) для презентации.

Запуск кампании (пример; ~16 ч на 12 ядрах, все 10 экспериментов):

```bash
.venv/bin/python -u ablation_campaign.py --workers 3 --threads 4 \
  --deadline 2026-11-13T07:00:00+03:00 --baseline-seconds-per-million 6500 \
  --output artifacts/campaign
```

Результаты: `artifacts/campaign/campaign_summary.json`, `campaign_report.md`,
`analysis.md`. Ключевые выводы — в `artifacts/night_*/report.md` (секция Hardening)
и на странице результатов (`#hardening`). GPU не ускоряет задачу: бутлнек в физике
MuJoCo, CPU и CUDA дают примерно одинаковую скорость. В наблюдаемых базовых запусках
5701 — верх диапазона 2571–5701 (среднее ≈3853; протоколы оценки различаются).
Один seed на PPO и TD3 не доказывает общее превосходство SAC; TD3 без action noise.

## Best-config агент (2026-11-13)

Применив рычаги из абляций — **сеть 256, lr=1e-3, batch=128, 1М шагов** — обучили 3
новых сида (50/51/52) через `best_config_campaign.sh`:

| сид | награда | ст. откл. | падения |
|---|---|---|---|
| **50 (hero)** | **5818** | 148 | 0% |
| 51 | 5362 | 701 | 3% |
| 52 | 5023 | 1256 | 3% |

Среднее **5401**, диапазон **5023–5818**, разброс **794** — против 3853 / 2571–5701 / 3130
у исходной конфигурации. Худший сид новой конфигурации (5023) выше среднего старой (3853),
падения 0–3% против 0–50% в этих запусках. Разные training seeds и протоколы оценки,
только три обучения на конфигурацию: превосходство не доказано. **Hero-модель — seed 50**; она по умолчанию в `demo_policy.py`
и в бандле. Графики: `best_config_plots.py`; видео: `make_rollout.py`.

## Follow-up: согласованное сравнение алгоритмов

Протокол, заранее фиксирующий три общих training seed (60–62), бюджет 1M и TD3
exploration noise, находится в `EXPERIMENT_PROTOCOL.md`. Запуск `followup_campaign.py`
создаёт отдельный каталог с логами и статусами; повторные запуски не перезаписывают
историю. Полученные метрики описывают конкретные конфигурации, не доказывают общего
превосходства алгоритма. Данные старой кампании экспортируются в `research/campaign/`
через `export_research_data.py`; производный индекс содержит SHA-256 первоисточников,
а исходная сводка не изменяется. Слайд `make_slide.py` читается из этих данных.
